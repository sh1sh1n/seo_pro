# Основной адрес товара

SEO Pro строит основной адрес карточки по текущим данным магазина и языка. Используйте этот контракт при настройке нового магазина до накопления публичных адресов. Миграция URL действующего наполненного магазина не включена.

## Основная категория и fallback

При включённой настройке `config_seo_url_include_path` полный адрес требует ровно одной отметки `main_category=1` среди привязок товара. Проверяются существование, статус, магазин, язык и связная иерархия всех категорий. Несколько отметок считаются неоднозначностью до отбрасывания недоступных категорий. Первая или минимальная категория автоматически не выбирается.

| Данные | Основной адрес |
|---|---|
| Путь включён, одна доступная основная, все keyword пригодны | `/category/leaf/product.html` |
| Путь выключен, keyword товара пригоден | `/product.html` |
| Нет основной, несколько основных или иерархия недопустима | `/product.html`, если keyword товара пригоден |
| Допустимая основная иерархия есть, но keyword категории/предка отсутствует | `/index.php?route=product/product&path=10_20&product_id=123` |
| Нет keyword товара, есть допустимая основная и путь включён | Тот же штатный адрес с актуальным `path` |
| Нет keyword товара, путь выключен или допустимой основной нет | `/index.php?route=product/product&product_id=123` |

Суффикс настраивается; `.html` — пример. Пустой keyword также непригоден для сегмента. Частичный ЧПУ с пропуском уровня не создаётся. Структурные `route/path/product_id` в штатном адресе сохраняются.

Импорт CSV/API не обязан вызывать сохранение основной категории через штатный интерфейс. Импорт без отметки получает короткие адреса; массовое назначение основной категории ради старых URL не выполняется. Исправление отметок может изменить основной адрес.

## Параметры и HTTP

Товарный генератор исключает производителя и контекст списка `sort/order/page/limit`. Страницы самих категорий, производителей и поиска сохраняют свои параметры. `filter/search/tag` и неизвестные имена не удаляются эвристически. Вложенные неизвестные параметры сохраняются. Совпадение имени функционального параметра расширения с одним из четырёх исключаемых требует отдельного решения по интеграции.

Аналитические значения сохраняются в href и 301, доступны обработчикам после перехода. HTML canonical карточки строится штатным вызовом с идентичностью товара и не копирует весь входной query. Canonical использует тот же полный, короткий или штатный основной адрес.

GET и HEAD устаревшего распознанного адреса получают один 301 на окончательную цель, включая XHR/fetch. Перед необходимым 301 startup один раз вызывает штатный `getProduct()`, проверяет исходного производителя и существование/доступность/структуру старой цепочки. Утрата привязки к существующей старой категории сама по себе допускает 301 в актуальную. Неверный, нулевой, текстовый или массивный производитель, недоступный товар, неизвестные сегменты и недопустимая цепочка не получают успешный переход.

На уже актуальном адресе startup не вызывает `getProduct()`; обычную проверку товара выполняет карточка. HEAD имеет тот же статус/Location при одинаковых условиях и пустое тело. POST/PUT/PATCH/DELETE и служебные маршруты не получают новый товарный 301. Клиенты должны поддерживать постоянные переходы; совместимость конкретных программных интеграций требует проверки.

## Прямые изменения MySQL и конфликты

После завершённой согласованной правки основной категории, иерархии или keyword следующий PHP-запрос читает актуальные адресные данные без очистки кэша. Внутри запроса положительные и отрицательные результаты повторно используются. Изменение нескольких таблиц должно оставлять согласованные `parent_id` и `category_path`. Модуль не исправляет повреждённые таблицы и не обещает мгновенно изменить уже построенный href посреди параллельной записи. Внешний HTML-кэш может отдавать страницу без PHP; его актуальность проверяется отдельно.

Keyword принадлежит первой строке по `seo_url_id` после SQL `LOWER(keyword)` и точного байтового сравнения результата. Учитываются все типы query, включая сторонние и неподдерживаемые. Недоступность первого объекта не передаёт имя второму. При нескольких пригодных alias одного объекта используется последнее непропущенное присваивание по ID, включая пустое значение. Для пустого значения применяется штатный fallback; более раннее имя не подставляется.

История переименований не создаётся. Старое имя обозначает текущего владельца либо даёт 404. Наличие другого адреса товара не превращает удалённый keyword в действующий.

## Совместимость и откат

Правило действует в штатной цепочке Url; сохранённый HTML и собственный JS-генератор не переписываются. Независимость от Deals сохраняется. Состав крошек и JSON-LD остаётся у ядра/темы; единая персональная история, Back и восстановление фильтра не реализуются. Дополнительные проверки стороннего контроллера, которых нет в штатной модели, могут не выполниться до раннего 301; такие расширения требуют отдельного теста.

Для отката сохраните исходные файлы и OCMOD 1.8, настройки пути и перечень модификаций. Эта архитектура не мигрирует данные каталога и не добавляет триггеры. Возврат файлов не отзывает 301, сохранённые клиентом или прокси. Проверяйте свежим клиентом, штатным URL и клиентом с сохранёнными переходами. Обратное переключение пути также требует проверки клиентских циклов. Установка и упаковка выполняются отдельным разрешённым действием.
